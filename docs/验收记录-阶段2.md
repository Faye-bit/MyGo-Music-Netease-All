## 已实现内容

- `home().sections[0].tracks` 提供真实日推，交给宿主原生 featureCard 展示。卡片未设置 `morePage`，点击直接打开宿主该分区详情，保持同批歌曲、封面与顺序；保留 `browse({page:"daily"})` 兼容入口并复用日推数据。
- 登录后首页改用个性化歌单接口；游客使用普通推荐接口并明确标注。日推空结果、普通网络失败及推荐歌单失败分别显示状态；会话过期仍走统一会话层。
- 雷达封面只取对应歌单；漫游、榜单及刷新入口缺少可信封面时使用宿主中性占位。展示首页和漫游列表不调用漫游取曲接口。
- 内存缓存键包含会话版本、账号 ID、中国日期和分区。日推同日复用，歌单推荐/雷达封面缓存 5 分钟；手动刷新、退出及重新登录使旧缓存和旧结果失效。跨中国日期重新请求服务器，不假定午夜或早上 6 点必然更新。
- 首页推荐请求合并，最多两个推荐任务并行；补歌曲详情在单任务内分批串行，完整详情直接复用。失败不写入成功缓存，仍受每次调用的 25 秒预算及请求超时保护。
- 漫游按模式串行追加，批内去重，过滤最近 500 首已返回歌曲。连续三批无新歌曲或服务端返回空批后停止，避免无限拉取；网络、权限和限流错误不盲目重试。停止后本次会话不自动继续该模式，重新启动/登录可重新开始。
- 不改动音质协议、宿主程序、账号权限和云端歌单写入能力。

## 接口与宿主对照

| 用途 | 逻辑接口或宿主行为 | 本版处理 |
| --- | --- | --- |
| 每日推荐 | `/api/v3/discovery/recommend/songs`，`data.dailySongs` | 按原顺序去重；缺少完整元数据/权限详情时补取 |
| 登录后歌单 | `/api/v1/discovery/recommend/resource`，`recommend` | 登录态首页和歌单详情页复用结果 |
| 未登录普通推荐 | `/api/personalized/playlist`，`result` | 明确标为普通推荐；不声称个性化成功 |
| 私人雷达封面 | `/api/v6/playlist/detail`，ID `3136952023`，`n=1` | 使用返回的 `coverImgUrl`；不借用其他歌单封面 |
| 雷达详情 | 同上，沿用完整歌单详情加载 | 账号校验后取曲；是否随账号变化尚待实测 |
| 缺失歌曲详情 | EAPI `/api/v3/song/detail` | 每批最多 400 首，复用已完整的推荐对象 |
| 私人漫游 | EAPI `/api/v1/radio/get` | 仅实际播放追加时请求，DEFAULT/FAMILIAR/EXPLORE 分别去重 |
| 日推布局 | 宿主 `browseLayout` 首分区有 tracks，页面 ID 为空 | 使用原生大卡片、内置详情页、播放与悬停效果 |
| 手动刷新 | `home-refresh:*` 页面，`setSetting({key:"refreshHome"})` | 失效插件缓存并重取；宿主首页缓存需用宿主刷新更新 |

宿主依据为固定提交 `1af0d8efd77fdf630c27cfc635f12e9cb089ce10` 的 [布局源码](https://github.com/egoist/mygo-music/blob/1af0d8efd77fdf630c27cfc635f12e9cb089ce10/internal/app/ui_browse.go) 和 [日推卡片源码](https://github.com/egoist/mygo-music/blob/1af0d8efd77fdf630c27cfc635f12e9cb089ce10/internal/app/ui_daily.go)。本次通过公开源码路径重新核对，GitHub 连接认证失败未影响后续源码获取。

## 性能观察与限制

- 确定性模拟：完整歌曲元数据的冷首页需账号请求 + 日推/个性化歌单/雷达封面各一次，不发歌曲详情请求；同分钟再次进入、打开日推和歌单详情不重复发推荐请求。缺少详情仅补缺项。该数字是模拟观测，不是真实网络抓包。
- 推荐任务的模拟最大并发为 **2**；401 首缺详情场景同样保持为 2。歌单全量详情仍沿用第一阶段的最多两个工作器。
- 本机页面、30 首日推、同批详情和短时播放可用；没有测量冷启动毫秒数、CPU、内存、真实网络请求数或滚动帧率，也不把自动化操作时间当作网络延迟。
- 插件不能直接清理 MyGo 的内置首页/详情页面缓存。手动刷新页先显示新数据，返回首页后需要宿主刷新，才能保证大卡片切换至新批次。只刷新宿主页面仍可命中插件当天缓存，说明中已明确。
- 尚未与官方客户端在相近时间逐项比较日推和歌单；本机没有可直接沿用的官方客户端验收会话。本版没有自制随机推荐作为替代。
- 私人雷达固定 ID 的真实双账号差异、真实跨日、游客/断网/部分失败的实机展示、账号切换的实机结果、长时间私人漫游追加仍待验证；相应模拟检查已完成。
- 第一阶段遗留的云端写入、非空喜欢、大歌单等实机验收不在本次伪造补齐。音质与菜单栏播放器不属于第二阶段。

## 0.2.1 首页修订

用户反馈：首页刷新卡片多余，排行榜及三种漫游的中性占位被视为缺失封面。本次移除首页刷新卡片，保留设置刷新；为排行榜、私人漫游、熟悉的歌、新发现分别添加榜单玻璃柱、红色唱片、琥珀磁带、蓝色星轨主题封面。它们是导航主题图，不是官方队列预览；日推和雷达仍使用真实对应内容。

四张图片由图像生成工具创建，随仓库 `assets/` 及 0.2.1 Zip 分发。通过宿主 `host.dir` 和 `file://` 路径读取，空格及非 ASCII 路径编码已覆盖；不新增联网权限、不依赖远端图片，也不提前调用漫游取曲。根清单安装和 Zip 均在安装根目录提供 `assets/`。旧版只含五个文件的包结构由本版扩展为九个文件。

`npm run check`、52 项测试及 `npm run package` 通过；现有测试已调整为核对排行榜/三个漫游封面路径、三个封面互异、首页不存在刷新卡片，原有不预取漫游及去重保护仍通过。

本机从 0.2.1 Zip 更新九个发行文件并逐字节核对，未读取或修改会话存储。重启后确认探索分区只剩雷达、个性化歌单、排行榜三个入口；排行榜主题图正常显示。向下滚动确认三个漫游封面分别显示红色唱片、琥珀磁带和蓝色星轨，均不再出现缺图占位；播放器保持原歌曲暂停状态。

## 0.2.3 日推导航与文案

侧栏新增「每日推荐」及宿主 calendar 图标，移除重复的喜欢入口和同步入口。底部账号的 profile.page 仍指向同步页，原有功能没有删除。首页日推详情 pageTitle 调整为「每日歌曲推荐」，说明为「根据你的音乐口味生成」；侧栏 daily 浏览页补充中国日期、星期、实际歌曲数。沿用日推缓存，不为导航重复读取整批详情。

语法检查、52 项测试和九文件打包校验通过，现有日推用例补充标题/说明/日期断言。本机更新 0.2.3 的发行文件后逐字节核对，未修改用户存储。重启确认侧栏为「发现音乐、每日推荐、私人漫游、排行榜、我的播客」，下方喜欢歌单仍在。侧栏日推实际返回「每日推荐 · 11月8日 星期日 / 每日歌曲推荐 / 30 首 · 根据你的音乐口味生成」，前三首为 Your Eyes、For フルーツバスケット、Fabulous，播放器原歌曲保持暂停。
