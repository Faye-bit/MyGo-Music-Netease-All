# 网易云音乐接口可行性调研

调研日期：2026-11-08。范围：独立替代现有插件，按登录、首页、音质三个阶段开发；菜单栏播放卡片不在本次范围。

## 1. 结论与证据边界

**有可行的实现路线，但目前不能承诺“仅使用官方公开开放 API”就完整满足全部需求。**

必须区分两类接口：

1. **官方开放平台**：网易已提供开发者入驻、应用凭据和官方 `@music163/ncm-cli`。官方发布的资料包含用户授权、搜索、歌单管理、每日推荐与播放能力。它值得优先验证，但本次没有取得完整接口文档、应用凭据和真实授权，尚不能确认全部歌单操作、私人雷达、音源直链、音质选择及实际音质元数据的覆盖程度。
2. **网易云客户端使用的接口**：现有 `sogud/mygo-music-netease` 直接访问 `music.163.com` 和 `interfacepc.music.163.com`，已经实现扫码登录、歌单、推荐和音源请求。这些是访问网易服务器的第三方适配实现，**不等于网易公开承诺稳定性的开放 API**。

本次完成了公开资料与源码核查，没有进行账号登录、个人数据读取、歌单写入或真实音频播放。下文“已有实现”表示代码路径存在，不表示本次在线实测通过。第三方封装的 `/login/qr/key`、`/song/url/v1` 等路由也不能直接当成网易官方端点。

官方开发者文档页面在本次抓取中无法读取；npm 页面返回 403，包元数据网络请求亦失败。因此官方路线保留为需要补充验证的选项，不编造其 HTTP 端点、鉴权参数或额度。

## 3. 官方开放平台是否够用

官方发布资料确认存在开发者入驻和 `appId` / `privateKey` 配置，以及用户登录授权流程；它与现有插件的二维码 Cookie 会话并非已经验证可以互换的登录体系。[官方项目说明][O1]

官方工具文档还描述了使用 mpv 播放或唤起 macOS 网易云客户端播放。但“CLI 可以播放”不直接证明 MyGo 插件可以获得同样的音源地址、选择 Hi-Res，或无需外部进程即可复用这些能力。[安装与播放配置][O2]

| 本项目要求 | 官方公开资料能支持的判断 | 尚需验证 |
| --- | --- | --- |
| 登录与用户信息 | 有授权与用户信息能力 | 能否符合插件内扫码体验、回调方式、刷新和撤销机制 |
| 歌单与喜欢列表 | 有歌单管理、收藏及红心数据相关说明 | 自建/收藏歌单完整分页、顺序、喜欢与取消喜欢、增删曲目覆盖 |
| 首页日推 | 有每日推荐能力 | 返回字段、更新策略，与官方 App 同账号结果的关系 |
| 个性化歌单、私人雷达、漫游 | 不能仅凭泛称“推荐”确认全部覆盖 | 专用接口和连续推荐状态 |
| 播放 | 有工具层面的播放能力 | MyGo 可直接消费的完整音源、有效期、请求头和授权范围 |
| 无损、Hi-Res及准确标识 | 本次资料不足 | 档位、会员权益、实际格式/码率/采样率字段 |

官方资料同时区分加密资源 ID 与原始数字 ID。若后续采用开放平台，必须保存明确的 ID 映射，不能把一种 ID 直接用于另一条路线。[官方工具说明][O3]

**路线建议**：首版以现有插件的客户端接口实现为基础，保持可替换的请求层；在阶段一预研中验证开放平台能否完整覆盖。如果覆盖全部关键能力且能适配 MyGo，再选择官方路线。不要在证据不足时拼接两套会话与 ID，也不要为了调用 CLI 默认引入 Node、mpv 或额外播放器。

## 4. 现有客户端接口能力清单

以下均来自现有插件源码。[插件实现][P1] 表中 `/api/...` 是源码中的逻辑路径；经过 `eapi()` 的请求实际发送到 `https://interfacepc.music.163.com/eapi/...`，普通 `request()` 发送到 `https://music.163.com/api/...`。不可省略请求编码、会话和响应处理后直接照抄 URL。

| 能力 | 逻辑端点 / 入口 | 当前依据与限制 |
| --- | --- | --- |
| 扫码 key | `/api/login/qrcode/unikey` | `type: 3`，EAPI |
| 扫码轮询 | `/api/login/qrcode/client/login` | 处理 800/801/802/803；成功后验证会话与账号 |
| 账号信息 | `/api/nuser/account/get` | 当前实现读取用户信息、判断登录状态 |
| 退出登录 | 插件本地清理会话 | 不调用全局退出接口，不应退出其他设备 |
| 账号歌单 | `/api/user/playlist` | 自建/收藏区分；每页 200，现有实现最多约 2000 个歌单后报错 |
| 歌单详情 | `/api/v6/playlist/detail` | 当前仅装载前 1000 首并提示，不能把此行为称为完整同步 |
| 歌曲详情 | `/api/v3/song/detail` | 分批补齐详情、权限并恢复原顺序 |
| 喜欢列表 / 喜欢操作 | `/api/song/like/get`、`/api/radio/like` | 已有读取和写入实现 |
| 歌单增删曲目 | `/api/playlist/manipulate/tracks` | 已有写入与结果核对；不能盲目重试写请求 |
| 每日推荐歌曲 | `/api/v3/discovery/recommend/songs` | 登录后读取 `data.dailySongs` |
| 个性化歌单 | `/api/v1/discovery/recommend/resource` | 登录后读取 `recommend` |
| 普通发现歌单 | `/api/personalized/playlist` | 首页当前使用；不能仅据端点名称断言是游客结果 |
| 私人雷达 | 歌单详情 + ID `3136952023` | 当前插件的固定入口；是否按账号动态变化需实测 |
| 私人漫游 | `/api/v1/radio/get` | DEFAULT/FAMILIAR/EXPLORE；连续结果与去重需验证 |
| 心动模式候选 | `/api/playmode/intelligence/list` | 源码存在但未在默认入口开放，不作为已完成公开能力 |
| 音源 | `/api/song/enhance/player/url/v1` | 当前请求 standard/exhigh/lossless；检查试听、权限、URL和格式 |
| 歌词 | `/api/song/lyric`、`/api/song/lyric/v1` | 已有桌面接口回退 |

完整替代还须保留搜索、专辑、歌手、排行榜、评论读取、播客订阅列表与节目等，具体以开发计划中的导出函数清单验收。

## 5. 首页与宿主能力

MyGo 的首页首个分区如果包含 `tracks`，会展示内置日推卡片；该组件已有封面堆叠、唱片和悬停动画。现有插件却以 `links` 开头，因此没有触发它。优先修改数据结构即可复用，通常无需修改主程序。[布局实现][H2]、[卡片实现][H3]

现有入口封面来自普通发现歌单图片池，代码明确用于装饰，不能表示日推或雷达内容。应改为对应歌曲/歌单封面，缺失时用中性占位，不能随机借图。数据通过 `Browse` 结构交给宿主；插件并没有任意绘制首页组件的能力。[插件协议][H1]

## 6. 音质与宿主限制

当前宿主只定义 `standard`、`high`、`lossless` 三档；插件映射为 `standard`、`exhigh`、`lossless`。插件返回 `bitRate`、`type`、`quality`，但将 `hires` 合并为 `lossless`。播放页仅显示无损徽标。[插件音源实现][P1]、[宿主设置][H4]、[播放标识][H5]

原版截图的五档目标是：标准、较高、极高、无损、Hi-Res。其中 `higher` 与 `hires` 应作为待验证请求候选，当前插件没有完整请求实现；192k/320k是档位描述，不能替代对实际返回码率的检查。

**纯插件可先交付准确的三档音源适配，但无法承诺原生五档下拉框和 Hi-Res 独立徽标。** 插件文本设置可以研究为临时偏好入口，但不是完整解决方案：宿主可能在调用插件前直接命中缓存。

宿主缓存按来源、歌曲和音质建键，并允许复用更高档缓存。只在插件中把 `lossless` 偷换为 `hires`，可能仍播放已缓存的普通无损，或错误标识实际档位。[缓存实现][H6] 五档完整体验需要协调宿主音质枚举、偏好传参、缓存和标识；这项依赖必须保留在第三阶段，不能以插件设置宣称已经完成。

## 7. 开发前/过程中必须补齐的实测

- 核对本机版本、可用宿主协议和当前插件公开功能；不读取旧插件 Cookie 作为默认迁移方式。
- 用户在插件中扫码，验证重启恢复、过期重登、退出及切换账号后的数据隔离。
- 对比自建/收藏/喜欢歌单的 ID、顺序、数量；用大歌单验证超过 1000 首的处理。
- 同一账号、相近时间核对日推与个性化歌单。雷达结果不能仅凭固定 ID 就认定个性化有效。
- 用当前账号有权限的免费、会员、无损、Hi-Res歌曲验证完整音频；权限不足、仅试听、无对应音源均需区分。
- 记录请求档位、返回档位、格式、码率与实际缓存命中。对返回的 Hi-Res 音频进一步验证可解码性；不能从 FLAC 扩展名推断 Hi-Res。
- 官方开放平台若可访问，补齐文档与应用授权验证，确认是否允许目标接入方式、是否能返回 MyGo 所需音源；不得把私钥写入公开插件包。

接口变更、限流、账号风控和无权限返回是持续维护因素。预期只做有限重试、明确提示和手动重登，不通过高频请求、公开代理或替代音源掩盖失败。
