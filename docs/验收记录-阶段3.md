## 实现与验证

- 三档 `standard/high/lossless` 分别请求 `standard/exhigh/lossless`；未来协议候选 `higher/exhigh/hires` 有明确映射。拒绝未知输入，不提供绕过宿主缓存的文本偏好。
- 请求档位、实际档位、服务端声明及宿主分类分开记录。支持 mp3/flac/ogg，缺少格式时失败；FLAC 归宿主无损，只有服务端明确返回且格式一致才记录实际 `hires`。缺字段或格式与声明矛盾时实际档位为 `unknown`，不继承请求档位，不推断采样率/位深。
- 返回宿主仍使用三档：`higher/exhigh` 归 high，`lossless/hires` 归 lossless；保留详细档位在脱敏摘要中。缺档位时 FLAC 只确定无损；有损按已知码率分类，信息不足保守归 standard，避免宿主按请求的无损缓存有损文件。
- 拒绝试听、空地址、权限失败、缺失/不支持格式、无效或非受支持网易域名地址及显式无效有效期。有效数值的大小、码率、有效秒数和服务端提供的采样率/位深进入摘要；不保存 Cookie、音源 URL、歌曲 ID 或原始响应。
- 接受服务端直接返回的完整低档音源；没有客户端逐档降级。风控、限流、鉴权、网络及超时失败直接报告，不通过换档掩盖。与旧版不同，460/-460 风控拒绝不再自动重试。
- 同一会话、同曲、同有效请求档位合并进行中请求（high 与 exhigh 合并）。成功及失败后均释放；后续调用重新取流，不缓存地址。退出、切换账号、会话失效后，旧结果不能返回或更新诊断。
- 每次请求使用会话和 25 秒调用预算，单次网络超时上限仍为 12 秒；无额外重试和并发逐档探测。无需添加网络权限或运行时依赖。

`npm run check` 通过；`npm test` **69 项通过，0 失败**：第一阶段 36 项（更新风控行为与诊断字段断言）、第二阶段 16 项、第三阶段 17 项。测试只使用虚构会话和模拟响应。覆盖候选五档映射、服务端降档、缺失/矛盾元数据、可选字段、脱敏、请求合并与释放、失效地址、权限/风控/限流/网络拒绝、退出竞态及未知偏好。原账号、歌单、首页、搜索、歌词、喜欢和基本播放的模拟回归全部保留。

## 本机抽样

沿用本插件已登录会话，未读取凭据或核验会员类型，未进行云端写操作。

1. 从宿主「插件 → 安装插件 → 从 Zip 文件」打开文件选择窗口并选择 0.3.0 包。安装操作期间工具报告用户改变了应用状态；重新读取后，设置明确显示 **网易云音乐 All 0.3.0、已登录、启用**，旧网易插件仍停用。以观察到的最终状态为升级证据，不将所有安装确认步骤写成自动执行成功。
2. 播放设置显示「音质：高」「下一首歌曲开始生效」。没有改变用户原有偏好、清空缓存或退出账号。
3. 从原有 30 首日推选择 **Verdurous Mountains / 渡辺雅二 / Ancient City**。播放器时长 **3:55**，实际进度从 0:00 推进到 0:03、0:06、0:09，最终暂停在 **0:16**；后续读取进度保持 15.675 秒。说明升级后有真实歌曲可短时解码播放，没有听完全曲或进行听感测量。
4. 底部账号进入同步页，云端目录显示自建 7 个、收藏 17 个、喜欢 0 首；再进入播放诊断，新版字段已实际展示：请求偏好 **high**，请求 **exhigh**，实际 **exhigh**，宿主 **high**，格式 **mp3**，码率 **320000 bps**，大小 **9413529 字节**，采样率与位深「未提供」。该摘要时间为北京时间 **15:34:26**。没有采集歌曲 ID；宿主存在预加载，故该摘要作为本次会话真实取流样本，不把其与当前歌曲的逐条归属视为已核验。
5. 本机只做非破坏性升级与只读/播放抽样。尚未进行本版重启、切换账号、三个设置逐一切换、断网和缓存命中矩阵；相应软件行为有模拟测试或源码核对，不能替代实机验收。

## 宿主依赖与缓存边界

核对本机保留的 MyGo 0.1.22 源码副本 `/private/tmp/mygo-stage2-host`。协议与缓存实现与接口调研所列固定基线一致；本次没有修改该副本或构建/替换主程序。

| 范围 | 当前行为 | 完整五档仍需的主程序工作 |
| --- | --- | --- |
| 枚举、偏好与传参 | `internal/music/music.go`、`internal/app/settings.go` 仅三档 | 增加 higher/exhigh/hires，兼容旧插件及旧偏好 high |
| 音源元数据 | `internal/music/music.go` 的 Stream 只有 quality/type/bitRate/size/gain/peak/headers 等 | 保存请求档位与实际档位、可选采样率/位深，缓存读回后仍可展示 |
| 实际播放标识 | 当前播放页只区分无损标识，无法独立展示 Hi-Res | 播放时从实际 Stream 读取档位；未知信息不得冒充已知 |
| 缓存顺序与键 | `internal/player/cache.go` 按来源、歌曲及三档建键，允许命中更高档缓存；写入优先采用返回的 quality | 明确五档排序/复用策略与旧缓存迁移，区分普通无损及 Hi-Res |
| 设置与预加载 | `internal/player/player.go` 在加载时读取偏好，可能复用缓存或 ahead 结果 | 验证设置改变后下一首的预加载失效/重取策略 |
| 账号变化 | 缓存键没有账号信息；插件退出只清业务状态 | 明确缓存的授权语义和账号隔离/重新校验方案 |
| 下载 URL 失效 | 插件每次调用重新取 URL；宿主失败不会回调插件 | 如需自动过期重取，在下载层增加受限重取/失效回调 |

本次保持宿主现有「允许复用更高档缓存」行为。插件没有清除缓存的接口，未删除现有音频文件，也不声称退出后缓存必经新账号授权。诊断是最近成功取流，宿主命中缓存或预加载时可能不会再次调用插件，不能把摘要当作当前播放的实时档位。

完整五档的配套测试构建至少应覆盖：先普通无损再选 Hi-Res；先高档缓存再选低档；选择严格匹配或高档复用后的实际标识；重启旧缓存兼容；换账号的缓存权限语义；下一首预加载；限流/过期时受限重取。按 Plan，本次不发布上游 Issue 或 PR。
